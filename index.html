EXPERIMENT · MLPs, A CNN, TRANSFORMERS UP TO 163M · RENTED COLAB GPUs, AN AGENT AT THE WHEEL

Can a network learn without backprop if you just show it the answer?

I'm Cuper. Every neural network you've heard of learns the same way: it guesses, then runs a second pass backwards through itself to work out who to blame, the backward pass. I wanted to know whether you could skip that. Run the network twice instead, once normally and once with the right answer quietly fed in, and let a small learned network turn the difference into weight updates. I wrote the plan as a ladder of experiments with a pass-or-fail gate on each rung, from handwritten digits up to a GPT-2-sized model, and had an AI agent build and run all of it on rented GPUs. The answer is mostly no, and this page has every rung where it failed. Hover or tap any underlined word for a quick picture of what it means.

What's wrong with the backward pass?

Nothing, mostly. Backprop is the reason deep learning works. But it's one fixed rule: for every weight, multiply what came in by how much it should have come out differently, the gradient. That's only guaranteed to be right for an infinitely small step on one batch. Everyone then bolts an optimizer like Adam on top to make the steps sensible.

My idea, which I called the Hindsight Editor: run the network twice, in parallel. The blind pass is the normal one. The sighted pass uses the same weights but gets the correct answer injected into every layer through a small side channel. The difference between the two at each layer, the hindsight delta, says which way that layer "wished" it had gone. Then a small learned network, the editor, reads those deltas and writes the weight updates. No backward pass ever touches the network being trained.

Does showing the answer even point the right way?

The first rung was plumbing. A small network reads handwritten digits (MNIST), and I check whether the delta at each layer points the same way backprop would push. To make the sighted pass actually carry the answer through every layer, each layer gets a tiny readout trained to recover the answer from it.

E0 PASSIt does point the right way, at every layer, but weakly in the hidden ones: a cosine of about 0.14 and 0.22, against 0.70 at the output. The readouts are what make it work. Without them the delta is exactly as useful as noise, and so is the classic random-feedback trick, at least on a network trained by backprop.

Plot twist: knowing the answer isn't knowing the mistake

Applying the delta directly as an update failed hard. On digits it reached 15 percent, barely above guessing, and it diverged at every learning rate. The reason is simple once you see it. Injecting the answer pushes every example toward the right digit, even ones the network already gets right. Backprop's signal is the error, the right answer minus the network's guess, and it fades to nothing once the guess is right. My delta encoded the answer, not the mistake, so it never stopped pushing.

The fix keeps both passes parallel and needs no gradient, which made it the most useful idea in the project. The sighted pass responds roughly in a straight line to whatever code is injected. So for each batch I measure that response by regression, then subtract the part the blind pass already predicted. I call it linear correction. Two more things had to change. The answer injected at the output layer must be the answer itself: a learned map there rotates the error and drives the outputs the wrong way. And each example gets weighted by how wrong the blind pass was, which is just its loss, computed on the way forward.

How does a small network write a weight update?

The editor has to be cheap, or it's pointless. It reads each layer's inputs and deltas, reshapes them with tiny learned functions, and writes a low-rank edit: a handful of directions instead of a full matrix, in the spirit of model-editing networks like MEND and RLEdit, except they read gradients and this one reads hindsight.

My first compression mixed examples together with random signs, and it destroyed the signal. In the hidden layers, the edit's alignment with the right direction dropped from about 0.2 to zero. Swapping in a randomized range finder kept essentially all of it. Rank turned out to matter a lot: rank 1 gets 37 percent of digits right, rank 16 gets 87.

Can it learn by copying Adam?

The plan's first training phase was imitation: train the editor to reproduce Adam's updates, with backprop used only to make the answer key. It made things worse, down from 88 to 70 percent. Adam scales every weight separately; a low-rank edit can't express that, and trying to match Adam's step size crammed all the movement into a few directions and blew the network up.

E1 FAILThe untrained editor on the corrected delta got to 87.9 percent, against backprop's 98.4. The gate asked for "within a few points". It missed by ten, and also lost to plain random feedback at 96.9.

What if it learns from its own results?

That's phase two, cutting the cord. The editor edits a fresh network for 16 steps, then it's graded on one thing only: how much lower the loss is on data it hasn't seen. That grade trains the editor through all 16 steps, a setup called meta-training. The network being edited still never sees a gradient, and the code asserts it.

This was the part that worked best. Accuracy climbed from 87.9 to 90.0, then 94.8 percent once the editor saw longer stretches of training, from networks at different stages, with a slower learning rate of its own. Swapping the parallel sighted pass for a sequential one that first sees the network's guess, like Forward Target Propagation, got to 96.0. Within 2.4 points of backprop.

Is it worth the compute?

This was the measurement the whole project was built around: at equal compute, which lowers held-out loss more per update, a backprop step with a tuned Adam or a Hindsight Editor step? An editor step costs about 85 percent of a backprop step: two forward passes plus the editor, against one forward and one backward.

E2 FAILAdam wins at every budget I measured. Over the very first 25 updates, the meta-trained editor lowers the loss about 40 percent as fast per update as Adam does, and at equal compute its held-out loss stays two to three times higher all the way out. A first, coarser version of this chart seemed to show the editor ahead early on. That was an artifact of evaluating Adam only every 500 steps, and it went away when I measured every 25.

Does the hindsight even matter?

A little. Feeding the same meta-trained editor random feedback instead of hindsight costs about one point of accuracy. But random feedback is about 45 percent cheaper per update, so at equal compute the two end up close. The sequential pass that sees the network's guess first is the best signal. The editor's view of each layer's inputs adds nothing. And letting the hindsight signal travel through the layers, instead of only being injected at each one, diverges every time. A layer trained toward its own amplified reaction to the answer forms a feedback loop.

Can it see pictures?

Barely. On CIFAR-10, Adam reaches 74 percent and the best meta-trained editor 44. The recipe that worked on digits made the image network worse, 33 percent, and random feedback diverged at every learning rate I tried on these layers. At equal compute the editor's held-out loss was about twice Adam's.

Can it read?

No. For language, the "answer" is the next few characters, so the sighted pass gets a squeezed summary of them through a narrow bottleneck, optionally with an information penalty so it can't just copy the answer through. I tried widths 4, 16 and 64, with and without the penalty.

E3 FAILAdam brought the loss down to 1.11 nats, or 1.6 bits per character. Every editor I tried, untrained or meta-trained, at every bottleneck width, stayed at the unigram level of 3.51: it learned which letters are common and nothing else. Along the way I found a real bug: in the transformer, six of the seven hindsight channels were never trained. I fixed it and wrote a test for it, and the result didn't change.

Why does it fail on bigger networks?

To separate "language is hard" from "big networks break it", I generated a toy language where each token strongly predicts the next one. On a tiny transformer, the editor learned it almost as well as Adam (1.06 against 0.91, where letter frequencies alone give 3.82). Then I changed one dimension at a time. A longer context was fine. Six layers mostly broke it. Making the layers wider, 384 instead of 64, broke it completely.

So the failure is about width, not about language. My best guess at the mechanism is the compression: a rank-16 edit can only move 16 directions in a layer, and that's a shrinking share of what needs to move as layers get wider. I also found that the editor's default step size was about ten times too small for transformers. Fixing that was necessary but not enough.

What happens at GPT-2 size?

The plan said to run it anyway and report whatever happened. AdamW with the published GPT-2-small settings reached 4.32 nats on FineWeb-Edu text, against 7.68 for knowing word frequencies. A higher learning rate did worse, 5.76. The editor, with layers twice as wide as the ones that already broke it, diverged within the first 500 steps. The rented machine running it vanished 60 percent of the way through, at step 4,600 of 7,700, with nothing in the log to say why. It had been diverged the whole way, so I didn't pay to finish it.

Can it improve itself?

The last rung was the stretch goal: let the editor edit its own weights, with no gradient. Each step it nudges its own settings in a random direction, applies its edit, checks whether held-out loss went down, and keeps nudging in directions that helped. That's weight perturbation using its own results as hindsight, in the spirit of self-referential weight matrices.

E5 FAILIt wasn't stable, and it didn't improve. A single batch of results is mostly noise, so the editor's own step size went on a random walk: up until training exploded, or down until it froze. The meta-trained editor went from 95.3 percent frozen to 76 percent editing itself, at 76 percent more compute per run.

Who else is working on this?

Plenty of people, and the closest pieces of this are theirs:

  • Learning without a backward pass. Lillicrap et al. showed random feedback weights can train networks, and Nøkland sent the error straight to every layer (DFA), the random-feedback baseline here. Forward-Forward, PEPITA, Signal Propagation and NoProp feed the label or the error in through forward passes. Forward Target Propagation uses a second pass for per-layer targets, the sequential variant that did best here.
  • Learned editors and optimizers. MEND, MALMEN and RLEdit turn gradients into low-rank edits. VeLO and Celo2 are learned optimizers, and both still read gradients. Persistent evolution strategies are the obvious fix for my short-horizon meta-training.
  • Self-modification. Self-referential weight matrices update themselves without gradients at small scale. SEAL has a language model write its own training data, then applies it with ordinary gradients.
  • Backprop-free language models. Recent work trains language models with local losses or forward gradients at hundreds of millions of parameters (local learning for LM pretraining, SOLO, split forward gradients), with gaps to backprop far smaller than mine.

What this page adds is narrow: a learned update rule fed only by a parallel "shown the answer" pass, a fix that turns that signal into an error signal without a gradient, and a full ladder of honest tests. Most rungs failed, and they're all here with the numbers that failed them.

How did I build it?

I wrote the plan as a handoff document: the idea, the ladder, the gates, the rules. An AI agent (Claude) built everything from it and ran it through the Colab command line on rented RTX PRO 6000 GPUs, with quick checks on my laptop's RTX 3060. That covered the library, the experiment runner, an on-machine supervisor that saves to a private Hugging Face repo and shuts its own machine down, and the analysis. My connection is bad. Launches failing on it cost about 13 of the roughly 88 compute units the whole ladder used, before the launcher was hardened against it.

Several early results were wrong in ways that looked like findings. Each fix made the conclusions smaller and more trustworthy. The setup, the numbers and the limitations are in Lab notes.

Setup

PieceWhat it was
Hindsight channelPer layer, the code (centered one-hot answer, or for language a discounted summary of the next 8 tokens through a width-w bottleneck) is mapped by Cl and added to that layer's state. The logits' channel is the identity. Channels and readouts are trained only by a local readout loss; the sighted pass sees detached weights and cuts gradients between layers.
Linear correctionPer batch, ridge-regress each site's delta on the injected code (K × F), then d~ = d − (p − 1/K)M. Language: subtract the code expected from the blind pass's next-token distribution; the head gets β(onehot(y) − p).
EditorElement-wise MLPs on row-normalized factors, conditioned on layer kind, depth and row statistics; per-example weights from the blind loss; rank-r edit Q(DQ)TA/N via a randomized range finder; learned step size and momentum; trust region of 2–5% of the layer's weight RMS.
Meta-trainingHeld-out log-loss after K edits (K = 8–16), backprop through the unroll into the editor only; fresh networks every 1,000–2,000 inner steps, some warm-started by Adam; reset on divergence; skip non-finite updates. Main-network weights never require or receive gradients (asserted, and unit-tested).
ModelsMNIST MLP 784-256-256-10; CIFAR-10 CNN 32-64-128 conv + 256 fc; char GPT d=384, 6 layers, ctx 256, 10.9M; FineWeb-Edu GPT d=768, 12 layers, ctx 1024, vocab 50,304, ~163M (untied embeddings).
ComputeColab G4 (RTX PRO 6000, 96 GB) at 8.9 units/hour, many jobs packed per GPU; quick checks on a laptop RTX 3060. About 88 units by the ledger, ~13 of them lost to launch failures.

Fixes, in the order they were found

  • Raw parallel delta encodes y, not y − p: linear correction plus per-example error weighting.
  • A random or learned map at the logits rotated the error: identity output channel.
  • Random-sign batch sketches drowned the signal: randomized range finder.
  • RMS-normalized edits removed the error's size and diverged: unnormalized edits, learned step size, trust region.
  • Propagated deltas form a Hebbian loop: propagation weight α = 0 (α > 0 diverges, even meta-trained).
  • Meta-training instability: divergence resets, skip non-finite updates, slower meta learning rate, longer unrolls, warm-started trajectories.
  • Transformers: step size about 10× too small; six of seven hindsight channels never trained (bug, fixed and tested); vocab padding mismatch at 50k tokens (bug, fixed).
  • Measurement: editor evaluated on different initial networks than Adam (rerun on the same ones); an early "editor ahead" reading was an interpolation artifact (re-measured every 25 updates).

What I wouldn't lean on

  • Each rung got one or two focused fixes before moving on, by design. Better editors surely exist; this tests one family carefully, not the idea exhaustively.
  • Meta-training used short truncated unrolls (up to 16 steps), which are known to favor greedy updates.
  • E4 is one seed and only 98M tokens, with no meta-training at that scale.
  • The ablations of the meta-trained editor use one meta-training seed each (three test networks).
  • Wall-clock is confounded: many jobs shared one GPU, and the editor runs as unfused Python. Charts show compute, not time.
  • The width diagnosis comes from a synthetic language and one bisection; the rank-starvation mechanism is a hypothesis, not a measurement.
